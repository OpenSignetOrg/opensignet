## Accounts

You sign in to [opensignet.com](https://opensignet.com) with Google, an email code or a wallet
(EIP-4361). There is no separate sign-up, and each person has one account across these methods.
A signed-in session belongs to the account, whichever method started it.

Every account comes with its own OpenSignet wallet on Base, created with the account. While the
owner is signed in it pays OpenSignet (plans, domains and their renewals) without a code; sending
funds anywhere else, exporting its key and changing its approvers need the owner's approval (an
email code or their linked wallet). **Withdraw** in the wallet settings sends USDC to any address
on Base after that approval; OpenSignet pays the network fee and emails a receipt with the
transaction. You can also link an outside wallet to the account.

Cards are saved on Stripe's own page, at a card checkout or with **Add card** in the wallet
settings. OpenSignet keeps only the brand, the last four digits and the expiry. The default card
pays whatever is set to renew by card.

An account owns the identities it registers. Each identity's OpenSignet Pass is held by the
account's OpenSignet wallet and never moves. Managing an identity (DNS, email, API keys, renewal
and settings) uses the account session, an API key scoped to the identity, or a wallet request
signature from the account.

## Identity bundle

An OpenSignet registration coordinates public internet and onchain identity into one owner-scoped
record. Depending on the selected options, the bundle contains:

- a registered internet domain;
- managed DNS;
- a primary email address;
- an OpenSignet Pass;
- an optional Basename on Base;
- an optional ENS name on Ethereum.

Basename and ENS are opt-in. The quote itemizes every selected component before payment.

## What you pay

A registration costs the domain at its registrar price, plus any Basename or ENS name you choose
and the current network gas. There is no platform fee. Registration is paid in USDC on Base.

Plans apply to the whole account. Every account starts on the Free plan (catalog key `included`),
which includes up to 3 identities, each with a primary inbox. Plus, Pro, Max and Enterprise add
identities and monthly email volume for the account, and API keys, DNS records and aliases for every
identity in it. Plans are
bought from the dashboard or the [pricing page](https://opensignet.com/pricing), by card through
Stripe or in USDC on Base, not during registration. See the
[plan limits](/api-reference/email/#primary-address-and-aliases).

## Owner and payer

The wallet paying for registration can also be the owner. `ownerAddress` records a different
owner address on the identity. The account that registered the identity manages it, whichever
wallet funded the checkout.

## OpenSignet Pass

The OpenSignet Pass is a non-transferable token on Base, one per identity, minted into the
account's OpenSignet wallet. It links the identity's domain with its Basename and ENS name and
nothing else, and it never moves between wallets. It is public on chain, and its metadata and
artwork are served at `https://opensignet.com/pass/<token id>`. When the domain leaves OpenSignet
(the account is deleted for good, the domain is transferred out, or it expires), the pass is burned.
Treat current API status and the pass as complementary signals: a pass alone does not prove
service health.

## x402 payment

Registration uses x402 v2 with USDC on Base. The first request can return `402 Payment Required`.
The client signs the accepted payment authorization and retries the same request with the standard
`PAYMENT-SIGNATURE` header. A successful response includes settlement information in
`PAYMENT-RESPONSE`.

## Provisioning states

Registration can finish immediately or continue asynchronously. The registration result reports
`provisioningStatus`:

| State               | Meaning                                                 |
| ------------------- | ------------------------------------------------------- |
| `completed`         | The selected identity services are ready.               |
| `processing`        | The request is accepted and still progressing.          |
| `recovery_required` | Support or an owner action is needed before completion. |

Registration progress also has its own `status` (`processing`, `completed`, `action_required`,
`failed`, `refunded`, `awaiting_payment`); see the [Registration API](/api-reference/register/).
Do not submit a second paid registration merely because a request is still processing.

## Renewal

Automatic renewal is a switch, on by default when you buy. The plan renews on the card it was
bought with, or from the OpenSignet wallet when it was paid in USDC. Each identity's domain renews
yearly, from 30 to 7 days before it expires, from the wallet or the saved card, chosen on the
identity's Domain tab. A change of method applies from the next renewal. A declined card is tried
once more a day later, with an email each time. The OpenSignet wallet signs a renewal only when
it falls due, only to OpenSignet and never above that item's ceiling, within the owner's one-time
approval. Code can read how a domain renews and switch it on or off; see
[renewals](/guides/renewal/).

## Identity profile

Each identity has a sender name and a logo, set at the top of its Domain tab and changed at most
twice a calendar month. The name is shown next to mail from the identity. A square SVG logo is
rebuilt as SVG Tiny PS and published as the domain's BIMI logo (`default._bimi`), which inboxes
that support BIMI show once the domain's mail passes DMARC with enforcement; Gmail and Apple Mail
also need a Verified Mark Certificate or Common Mark Certificate. PNG, JPG and WebP logos are
shown in OpenSignet only.
