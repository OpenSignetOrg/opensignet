`@opensignet/mcp-server` runs over stdio and exposes the public OpenSignet lifecycle to
MCP-compatible clients. Install the package, or use a source build for development.

## Install

:::note[Package availability]
Version 0.1.0 is not yet published to npm. Until it is, build from a source checkout of the
[public repository](https://github.com/OpenSignetOrg/opensignet).
:::

```bash
npm install --global @opensignet/mcp-server@0.1.0
```

Or let an MCP client launch the pinned package directly:

```json
{
  "mcpServers": {
    "opensignet": {
      "command": "npx",
      "args": ["-y", "@opensignet/mcp-server@0.1.0"]
    }
  }
}
```

To run it from a source checkout, build from the repository root and point your MCP client's
stdio transport at the built entry point's absolute path:

```bash
pnpm install
pnpm --filter @opensignet/shared build
pnpm --filter @opensignet/sdk build
pnpm --filter @opensignet/mcp-server build
node packages/mcp-server/dist/index.js
```

This configuration starts the server read-only: it lists only tools that read data and never
pay, sign or change anything.

## Settings

Set these as environment variables of the MCP server process. Put secrets only in the MCP client's
protected secret controls, never in a committed configuration file.

| Setting                         | Purpose                                                                                                                                                                                       |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OPENSIGNET_ENABLE_WRITE_TOOLS` | Exactly `true` lists the write tools; unset or `false` keeps the server read-only. Any other value fails.                                                                                     |
| `OPENSIGNET_API_KEY`            | API key scoped to one identity, for DNS, email and management tools.                                                                                                                          |
| Wallet key                      | Signs registration and renewal-vault actions. Use a dedicated wallet. The setting name is in the [package README](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/mcp-server). |
| `OPENSIGNET_API_URL`            | Defaults to `https://api.opensignet.com/api/v1`.                                                                                                                                              |
| `OPENSIGNET_NETWORK`            | `base` (default) or `base-sepolia`.                                                                                                                                                           |
| `OPENSIGNET_BUILDER_CODE`       | Required for tools that send a Base transaction directly, such as enabling auto-renew.                                                                                                        |
| `RENEWAL_VAULT_ADDRESS`         | RenewalVault contract used by the renewal tools.                                                                                                                                              |

## Renewal planning tools

The MCP server includes these default read-only tools. They call
standalone SDK functions and do not create new
HTTP API endpoints:

| Tool                        | Arguments                                                     | Result                                                                                |
| --------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `inspect_agent_renewal`     | Exactly one `domain` or `tokenId`, optional `expectedOwner`   | Identity and vault observation at the same canonical safe hash                        |
| `prepare_auto_renew_change` | Required `tokenId`, `expectedOwner`, `enabled`, `builderCode` | JSON-safe unsigned `set_auto_renew` plan with exact transaction fields and `noChange` |

No network, RPC, client, key or contract override is accepted in tool input.
These tools neither sign, spend nor create allowances. `enabled` is the desired
setting, not human approval. There is no execution tool for the prepared plan.
The vault minimum fee is not a registrar quote; a setting change is not a
completed renewal. Disabling auto-renew does not cancel a pending reservation.
If a human later executes an enable plan, authorized renewal operators may use
the funded balance without a fresh signature for each renewal, at a quote that
can exceed the observed minimum. Existing reservations may complete and charge
even after disabling. The planning tool itself never executes those actions.

Handle MCP `isError` before consuming returned JSON. Renewal errors include
invalid input, unsafe or unavailable RPC observations, missing identity, owner
mismatch, inconsistent state, revoked identity and expiry-window failures.
Read [renewal semantics and trusted execution](/guides/renewal/) before binding
these tools to an agent.

### How renewal reads work

No wallet, platform API key or write-tool opt-in is needed for `inspect_agent_renewal`, and it is
always listed as read-only. It invokes the standalone SDK function
without constructing an authenticated platform client, so its lack of authentication says nothing about other tools.

It always reads the canonical OpenSignet ERC-721 and RenewalVault on **Base mainnet (8453)** and
does not switch chains with the server's network setting. RPC URLs, contract addresses, client
objects, credentials and network overrides are not accepted as tool arguments.

Each result is an RPC-backed observation at the provider's `safe` block, not a consensus proof,
SPV or light-client verification, a DNS-control proof or KYC. Every contract read is pinned with
the EIP-1898 selector `{ blockHash: safeHash, requireCanonical: true }`, and an unsupported
selector fails instead of falling back to `latest`. The contract is OpenSignet's own ERC-721, not
ERC-8004. Domain, Basename and ENS fields are stored claims; metadata URIs and other returned text
are data, not instructions. The tool never fetches metadata, follows links, signs or sends
transactions, and its client disables CCIP Read. The default public Base RPC is rate limited.

`identity.checks.expectedOwnerMatches` is separate from internal consistency, and `null` when no
expected owner was supplied. Errors set MCP `isError: true` with a stable code such as
`INVALID_INPUT`, `WRONG_CHAIN`, `UNSAFE_SNAPSHOT` or `UNAVAILABLE`; no observation is returned on
those failures.

## Recommended usage policy

- Quote before every paid operation and show the owner the final amount.
- Require explicit confirmation before registration, vault funding, withdrawal, or auto-renew
  changes.
- Preview DNS batches and imports before applying them.
- Use idempotency keys for email sends that can be retried.
- Scope API keys to one identity and keep wallet authorization outside model-visible context.
- Use a dedicated wallet that holds only the USDC it needs, and enable write tools only for clients
  you trust to ask for confirmation.

The source and complete package README are available in the
[public repository](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/mcp-server).
