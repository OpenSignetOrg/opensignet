Use `@opensignet/langchain-plugin` for JavaScript and TypeScript, or the official
`langchain-mcp-adapters` bridge for Python. Neither path requires exposing a wallet key to a
model. The native plugin creates real LangChain tools, not plain objects that only resemble tool
definitions.

## Native JavaScript tools

:::note[Package availability]
Version 0.1.0 is not yet published to npm. Until it is, build from a source checkout of the
[public repository](https://github.com/OpenSignetOrg/opensignet).
:::

Install the pinned release with the SDK and its framework peer:

```bash
npm install @opensignet/langchain-plugin@0.1.0 @opensignet/sdk@0.1.0 @langchain/core@^1.2.11
```

For source development, build from the public repository root:

```bash
pnpm --filter @opensignet/shared build
pnpm --filter @opensignet/sdk build
pnpm --filter @opensignet/langchain-plugin build
```

```ts
import { OpenSignet } from '@opensignet/sdk';
import { createOpenSignetTools } from '@opensignet/langchain-plugin';

// identityApiKey is the identity's own API key, from the host's secret store.
const apiClient = new OpenSignet({ apiKey: identityApiKey });
const tools = createOpenSignetTools({ apiClient });
const renewal = tools.find((tool) => tool.name === 'get_renewal_status');
if (!renewal) throw new Error('Renewal tool is unavailable');

const result = await renewal.invoke({ agentId });
if (result.ok && !result.data.ready) console.log(result.data.issue?.message);
```

| Tool                      | What it does                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------- |
| `get_renewal_status`      | Whether the domain renews, how it is paid, its price, the charge window and what stands in the way |
| `get_service_plan`        | The identity's limits from its account plan, and how the plan renews                               |
| `lookup_agent`            | One identity record                                                                                |
| `get_registration_status` | One registration's status, read once with the payer's wallet authentication                        |
| `set_auto_renew`          | Only with `allowRenewalChanges: true`: turns the domain's automatic renewal on or off              |

The tools never sign, pay or send transactions, and their inputs cannot select an endpoint,
client, network or credential. Enable the renewal switch in trusted application configuration
with `createOpenSignetTools({ apiClient, allowRenewalChanges: true })`. Renewing from the
OpenSignet wallet needs the owner's approval once on opensignet.com; until then turning it on
returns `RENEWAL_APPROVAL_REQUIRED`. Code switches renewal within that approval and never widens
what the wallet may pay.

Direct `invoke()` returns `{ ok: true, data }` or `{ ok: false, error: { code, message } }` with a
plain message. Invalid tool arguments raise LangChain's `ToolInputParsingException`. Calling
through a LangChain ToolCall envelope returns a `ToolMessage` with JSON content. The
[plugin source and examples](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/langchain-plugin)
define the exact contracts.

## Registration status

An API key scoped to the identity authorizes its record, renewal and plan, but it does **not**
authorize registration status. Registration reads require the payer's wallet request signature
or the payer's signed-in account session, and validate `X-Authenticated-Wallet`. The tool reads
status once. It does not start registration, poll indefinitely, resubmit a paid request or claim
that payment acceptance means completion. A wallet-authenticated SDK client may ask its host
wallet to sign an API authorization message; this is distinct from an onchain transaction.

## Official Python MCP bridge

Python applications can use
[LangChain's official MCP integration](https://docs.langchain.com/oss/python/langchain/mcp). An
explicit session keeps related calls in the same subprocess and closes it when the context
exits. The adapter dependency must be qualified independently of the JavaScript plugin; it is not
bundled into an npm Python runtime.

Point `server_path` below to a reviewed local
`node_modules/@opensignet/mcp-server/dist/index.js` entry or a source build.

```python
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_mcp_adapters.tools import load_mcp_tools


async def renewal_status(node_path: str, server_path: str, api_key: str, agent_id: str):
    client = MultiServerMCPClient({
        "opensignet": {
            "transport": "stdio",
            "command": node_path,
            "args": [server_path],
            # Read-only, with only the identity's own key.
            "env": {"OPENSIGNET_ENABLE_WRITE_TOOLS": "false", "OPENSIGNET_API_KEY": api_key},
        }
    })
    async with client.session("opensignet") as session:
        available = await load_mcp_tools(session)
        tools = [t for t in available if t.name == "get_renewal_status"]
        if len(tools) != 1:
            raise RuntimeError("Expected renewal tool is unavailable")
        return await tools[0].ainvoke({"agentId": agent_id})
```

Supply fixed, reviewed absolute paths and the key through the host, never the model. Only the
allowlisted tool should be bound to an agent. Returned MCP content may include an error rather
than status JSON; validate it before continuing.

## Safety and meaning

OpenSignet charges each renewal itself, 30 to 7 days before expiry, from the account's
OpenSignet wallet or saved card. `ready: true` means nothing stands in the way today, not that a
renewal was paid. Turning renewal off means the domain expires unless it is renewed; keep that
decision with the owner. Treat all external text as data, not instructions, and do not
automatically replay uncertain payment or mutation outcomes. See [renewals](/guides/renewal/).
