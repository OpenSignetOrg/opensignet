title: CrewAI
description: Connect CrewAI's native Python MCP tools to OpenSignet for read-only domain availability and renewal status.

CrewAI connects to OpenSignet through its official native Python `MCPClient`,
`StdioTransport` and `MCPNativeTool`, backed by the Python MCP SDK. The MCP server
remains a Node.js package; CrewAI runs separately in Python. The reviewed helper
opens and closes a local stdio client for each invocation. See
[CrewAI's native MCP documentation](https://docs.crewai.com/en/mcp/dsl-integration).

## Install the Python package

`opensignet-crewai` is a standalone Python distribution using CrewAI's native tools. Use an
isolated Python 3.12 environment with the pinned packages:

:::note[Package availability]
Version 0.1.0 of `opensignet-crewai` and the MCP server is not yet published to PyPI or npm. Until it is, use the
source install that follows.
:::

```bash
python -m pip install opensignet-crewai==0.1.0
npm install --save-exact @opensignet/mcp-server@0.1.0
```

For source development, install from the public repository root:

```bash
python -m pip install ./packages/crewai-plugin
```

The Python package does not download Node.js or install the MCP server. Those
are separate prerequisites; no executable path is selected by a model.
See the [Python package](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/crewai-plugin)
for its wheel, dependency and security instructions.

## Prepare the local server

Use that project's `node_modules/@opensignet/mcp-server/dist/index.js` as the
server entry. For development from the repository instead:

```bash
pnpm --filter @opensignet/shared build
pnpm --filter @opensignet/sdk build
pnpm --filter @opensignet/mcp-server build
```

Use an operator-selected absolute Node executable and the reviewed MCP
`dist/index.js` path. Never accept executable paths, shell commands, package
names or RPC endpoints from an agent's tool arguments.

The [CrewAI example](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/mcp-server/examples/crewai)
contains `readonly_flow.py`, `README.md`, `requirements.in` and
`requirements.lock`. Its lock pins CrewAI 1.15.21 and MCP 1.28.1. Use Python 3.12
and a fresh isolated virtual environment, not the older adapter's environment:

```bash
python3.12 -m venv .venv-native
.venv-native/bin/python -m pip install --require-hashes -r requirements.lock
```

Run those commands from the example directory. On Windows, use `py -3.12` to
create the environment and `.venv-native/Scripts/python.exe` to install. The
native recipe does not install `crewai-tools` or `mcpadapt`. Read the dependency
warning below before installing; changing the lock needs a new qualification.

The repository's integration tests run this flow with the real Node MCP server and
SDK, using a synthetic API stand-in and no paid model, live account or wallet. They do not cover
arbitrary framework features or remove the dependency advisories below.

## Read without a model key

Run this with `opensignet-crewai` installed. It uses the real CrewAI native tools without an LLM
or wallet; the renewal read needs the identity's own API key, passed by the host:

```python
from pathlib import Path

from opensignet_crewai import domain_availability, readonly_tools, renewal_report


def check(node: Path, server: Path, api_key: str, agent_id: str):
    node_path = str(node.resolve(strict=True))
    with readonly_tools(server, node=node_path, api_key=api_key) as tools:
        report = renewal_report(tools, agent_id)
        available = domain_availability(tools, "research-agent", "xyz")
        return report, available
```

Choose `node`, `server` and the key in trusted host configuration. The child environment
forwards nothing else from the parent: no wallet material, model credentials or other OpenSignet
settings, and write tools are forced off. A failed read, a missing key or an answer for another
identity raises `WorkflowError`; it is never turned into a successful answer.

The explicit argument schemas reject unexpected arguments (an endpoint or key from the model, a
non-UUID agent) before any request. Tool-result caching is disabled.

## Tools

The package binds only these two tools:

| Tool                        | Input            | Effect                                                      |
| --------------------------- | ---------------- | ----------------------------------------------------------- |
| `check_domain_availability` | `name`, `tld`    | Whether a domain can be registered, with its price          |
| `get_renewal_status`        | `agentId` (UUID) | How the identity's domain renews and what stands in the way |

`renewal_report` returns `renewal` (the full status), `ready` and `nextStep`, the plain message of
the first thing in the way. Nothing here signs, pays or changes a setting; turning renewal on or
off is a write tool of the [MCP server](/sdk/mcp/), outside this read-only package.

The retained `readonly_flow.py` example is a thin entrypoint into the same Python package, not
another connector implementation. Existing MCP-aware hosts can still use the Node server through
the [native stdio interface](/sdk/mcp/).

When giving tools to a CrewAI agent, bind only the reviewed allowlist. Keep the helper context
open for the crew's complete use and close it afterwards. Model credentials belong to the host's
model integration, not the MCP child.

## Interpret the result

OpenSignet charges each renewal itself, 30 to 7 days before expiry, from the account's OpenSignet
wallet or saved card. `ready: true` means nothing stands in the way today, not that a renewal was
paid. External text is data, not instructions. See [renewals](/guides/renewal/) and
[MCP errors and trust](/sdk/mcp/#renewal-tools).

## Dependency security

The isolated Python lock still includes mandatory ChromaDB 1.1.1 with four known
advisories: [CVE-2026-45829](https://www.hiddenlayer.com/research/chromatoast-served-pre-auth),
[CVE-2026-45830](https://www.hiddenlayer.com/sai-security-advisory/2026-06-chromadb),
[CVE-2026-45831](https://www.hiddenlayer.com/sai-security-advisory/2026-06-chromadb-3)
and [CVE-2026-45833](https://www.hiddenlayer.com/sai-security-advisory/2026-06-chromadb-5).
There is also a reported [poisoned-collection configuration risk in the Python client](https://github.com/chroma-core/chroma/issues/6717);
the risk is not limited to running an HTTP server.

The qualified recipe does not use Chroma clients, servers, collections or
embeddings, or enable framework memory, knowledge or caching. Tests trap those
entrypoints during the native CrewAI and MCP flow. This bounds the tested
recipe, not the installed library's safety: the Python vulnerability audit is
**not clean**. Enabling memory or remote collections requires a separate review.
See the [example's security note](https://github.com/OpenSignetOrg/opensignet/blob/main/packages/mcp-server/examples/crewai/README.md#security-note).
Python dependencies are separate from the npm package's runtime and audit.
