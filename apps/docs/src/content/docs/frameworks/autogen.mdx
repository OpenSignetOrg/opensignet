Use Microsoft's `autogen-ext` MCP integration with `autogen-agentchat`, not an
unrelated similarly named package. The official `McpWorkbench` wraps an MCP
server and manages its session through an asynchronous context manager. See
[Microsoft's MCP reference](https://microsoft.github.io/autogen/stable/reference/python/autogen_ext.tools.mcp.html).

## Install the Python package

`opensignet-autogen` is a standalone Python distribution providing a guarded native AutoGen
workbench. Use an isolated Python environment; the native qualification uses Python 3.12. Install
the pinned packages:

:::note[Package availability]
Version 0.1.0 of `opensignet-autogen` and the MCP server is not yet published to PyPI or npm. Until it is, use the
source install that follows.
:::

```bash
python -m pip install opensignet-autogen==0.1.0
npm install --save-exact @opensignet/mcp-server@0.1.0
```

For source development, install from the public repository root:

```bash
python -m pip install ./packages/autogen-plugin
```

The Python package does not install Node.js or the MCP server. See the
[Python package](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/autogen-plugin)
for wheel and dependency instructions.

## Prepare the runtime

Use that project's `node_modules/@opensignet/mcp-server/dist/index.js` as the
server entry. To develop from a source checkout instead:

```bash
pnpm --filter @opensignet/shared build
pnpm --filter @opensignet/sdk build
pnpm --filter @opensignet/mcp-server build
```

The [native AutoGen example](https://github.com/OpenSignetOrg/opensignet/tree/main/packages/mcp-server/examples/autogen)
contains Python dependencies and the bounded workflow. Its dependencies belong
in a separate Python environment; npm installs only the Node.js MCP server.
Use the example's qualified Python dependency versions rather than silently
upgrading the MCP Python major version.

The repository's AutoGen integration tests run this flow with the real Node MCP
server and SDK. Its deterministic replay and synthetic API stand-in need no paid model, live
account or wallet; they do not cover arbitrary model providers.

## Use the standalone workbench

This source-build example uses the guarded package without a model key. The renewal read needs
the identity's own API key, passed by the host:

```python
from pathlib import Path
from opensignet_autogen import (
    OpenSignetWorkbench,
    domain_availability,
    renewal_report,
    server_parameters,
)


async def check(node: Path, checkout: Path, api_key: str, agent_id: str):
    params = server_parameters(node, source_checkout=checkout, api_key=api_key)
    async with OpenSignetWorkbench(params) as workbench:
        report = await renewal_report(workbench, agent_id)
        available = await domain_availability(workbench, "research-agent", "xyz")
        return report, available
```

The host selects absolute Node and built-checkout paths. For an installed MCP server package,
`installed_package=Path("/trusted/node_modules/@opensignet/mcp-server")` can replace
`source_checkout`. The `opensignet-autogen` CLI and `python -m opensignet_autogen` use the same
package; existing example entrypoints remain thin bridges, not independently maintained
implementations.

## Retained native MCP option

This direct invocation does not create an LLM client or need a model key:

```python
from autogen_ext.tools.mcp import McpWorkbench, StdioServerParams


async def renewal_status(node_path: str, server_path: str, api_key: str, agent_id: str):
    params = StdioServerParams(
        command=node_path,
        args=[server_path],
        env={"OPENSIGNET_ENABLE_WRITE_TOOLS": "false", "OPENSIGNET_API_KEY": api_key},
    )
    async with McpWorkbench(server_params=params) as workbench:
        return await workbench.call_tool("get_renewal_status", {"agentId": agent_id})
```

The host must supply fixed reviewed absolute paths for Node and the MCP entry point. Stdio starts
local code: do not let a model choose executable paths, arguments, packages or environment
overrides. Forward only the identity's own API key, never wallet material or model credentials.
Check the returned tool error state before interpreting the content.

## Bind an allowlisted workbench

The package's `OpenSignetWorkbench` limits both tool discovery and invocation to:

- `check_domain_availability`: a domain `name` and `tld`; whether it can be registered, with its price.
- `get_renewal_status`: an `agentId`; how the identity's domain renews and what stands in the way.

Use that guarded workbench when adding an LLM. Do not substitute a raw workbench that exposes
every discovered operation. Keep the context alive during agent use and close it on success or
failure. The model integration stays with the host; it is not supplied as an MCP sampling client.

## Interpret the result

`renewal_report` returns `renewal` (the full status), `ready` and `nextStep`, the plain message of
the first thing in the way. OpenSignet charges each renewal itself, 30 to 7 days before expiry,
from the account's OpenSignet wallet or saved card; `ready: true` means nothing stands in the way
today, not that a renewal was paid. Nothing here signs, pays or changes a setting. Handle errors as
errors, never as success. See [renewals](/guides/renewal/) and
[MCP trust and errors](/sdk/mcp/#renewal-tools).
